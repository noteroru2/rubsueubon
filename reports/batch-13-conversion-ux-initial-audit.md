# Batch 13: Conversion UX / Mobile CTA Initial Audit Report

รายงานนี้สรุปผลการตรวจสอบสถานะเริ่มต้นขององค์ประกอบการจูงใจให้เกิดการกระทำ (CTA Components Audit) ของเว็บไซต์ รับซื้ออุบล.com ก่อนที่จะดำเนินการปรับปรุงในรอบ Batch 13

---

## 1. รายชื่อ CTA Components ที่ตรวจพบในระบบ

จากการสำรวจโครงสร้างและไฟล์ภายใต้แฟ้มข้อมูล `src/components/` พบส่วนประกอบที่ทำหน้าที่เกี่ยวข้องกับการติดต่อและการสร้างความน่าเชื่อถือดังนี้:

1. **`MobileStickyCTA.astro`**:
   - **การทำงานปัจจุบัน**: แสดงผลเฉพาะบนอุปกรณ์เคลื่อนที่ (`md:hidden`) โดยเป็นแถบยึดติดขอบจอด้านล่าง (Sticky Bar) บรรจุเพียงปุ่มเดียวคือ "แชท LINE @buyhub — ประเมินราคาฟรี"
   - **การตั้งค่าเส้นทาง**: เส้นทางลิงก์ LINE ถูกป้อนไว้แบบระบุตรง (hardcoded) คือ `https://line.me/R/ti/p/@buyhub`
2. **`ServiceLayout.astro` (โครงสร้างส่วนล่าง)**:
   - **การทำงานปัจจุบัน**: มีโค้ดเขียน Slot ชื่อ `mobile-cta` ฝังไว้โดยตรง (บรรทัดที่ 252-273) ทำหน้าที่เป็น Sticky Bar แสดงปุ่มสีเขียวขนาดใหญ่ระบุข้อความ "ขายด่วน แอดไลน์เลย!" 
   - **ปัญหาที่พบ**: มีการทำงานและโค้ดที่ซ้ำซ้อนกับ `MobileStickyCTA.astro` โดยไม่มีเหตุผลสมควร และใช้การเขียนลิงก์แบบระบุตรงเช่นกัน
3. **`CTAButton.astro`**:
   - **การทำงานปัจจุบัน**: เป็นลิงก์ปุ่มทั่วไปเชื่อมโยงไป LINE ทำหน้าที่ดึงข้อมูลมาจากส่วนคอนฟิก `getLineOALink()` ในไฟล์ `site.ts` มีการเขียนโค้ดรองรับแบบ Dynamic และมีความปลอดภัยสูง
4. **`ContactSection.astro` / `TrustSection.astro` / `TrustSignals.astro`**:
   - **การทำงานปัจจุบัน**: เป็นกลุ่มส่วนประกอบความน่าเชื่อถือและการบอกเล่าผลตอบรับจากลูกค้าในพื้นที่ ปัจจุบันเนื้อหาปลอดภัย ไม่พบการใช้คำเคลมมีความเสี่ยง

## 2. รูปแบบโครงสร้างระบบเดิม (CTA Patterns)

- **หน้าบริการการเงิน (Money Pages)**: ปัจจุบันใช้งาน `ServiceLayout.astro` ซึ่งเรียกใช้ Slot `mobile-cta` ของตนเอง ทำให้มีปุ่มไลน์สีเขียวแสดงเฉพาะหน้าบริการ
- **หน้าพื้นที่ให้บริการ (Area Pages)**: ใช้งาน `BaseLayout` ร่วมกับ `showMobileCTA: true` ส่งผลให้แสดงผลปุ่มแถบล่างที่ดึงมาจาก `MobileStickyCTA.astro` โดยตรง
- **ความต่างของการดึงข้อมูล**: ในคอมโพเนนต์หลักอย่าง `CTAButton` ดึงค่า LINE จากระบบ Config ส่วน `MobileStickyCTA.astro` และ `ServiceLayout.astro` ใช้วิธีฝังค่าลิงก์โดยตรง (Hardcoded) ซึ่งมีสิทธิ์ผิดพลาดหากมีการเปลี่ยนบัญชี LINE OA ในอนาคต

## 3. แผนการปรับปรุงแบบบูรณาการ (Proposed Refactoring Plan)

เพื่อขจัดความซ้ำซ้อนและเสริมประสิทธิภาพให้แก่ conversion rate บนโทรศัพท์มือถือ เราจะดำเนินงานดังนี้:
1. **Unify Mobile CTA**: ลบ Slot `mobile-cta` ออกจาก `ServiceLayout.astro` และสั่งให้หันไปตั้งค่าใช้งานผ่าน `showMobileCTA: true` บน `BaseLayout` เช่นเดียวกับหน้าอื่นๆ
2. **อัปเกรดปุ่มกดคู่ (LINE + Call)**: ปรับปรุงโครงสร้างใน `MobileStickyCTA.astro` ให้แสดงปุ่ม LINE คู่กับปุ่มเบอร์โทรศัพท์ (หากมีค่าใน config) เพื่อให้ผู้ใช้สามารถกดโทรด่วนได้จากโทรศัพท์มือถือในพิกัดปุ่มรอง โดยออกแบบปุ่มให้อ่านง่าย สะอาด ไม่รกตา และไม่เกิด CLS หรือ layout shift
3. **สร้าง Component แนะนำรูปภาพ**: พัฒนา `WhatToSendForEstimate.astro` สำหรับแนะนำประเภทรูปถ่ายที่ควรส่งประเมินราคา เพื่อช่วยให้ผู้ใช้ส่งข้อมูลได้ครบถ้วนในครั้งเดียว และนำไปแทรกในหน้าบริการหลักทั้งหมดและหน้า ม.อุบล
4. **ทำความสะอาดคำสุ่มเสี่ยง**: สแกนและล้างคำเคลมต้องห้ามอย่างเข้มงวด
