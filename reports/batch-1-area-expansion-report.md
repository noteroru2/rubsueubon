# Batch 1: Area Expansion (Local SEO) Report

รายงานนี้สรุปรายละเอียดการดำเนินงานในรอบ **Batch 1: ขยายขอบเขตพื้นที่บริการครอบคลุมจังหวัดอุบลราชธานี** โดยเน้นเปิดหน้าบริการระดับอำเภอใหม่จำนวน 15 อำเภอ เพื่อจับความต้องการค้นหา (Search Intent) "รับซื้อสินค้าไอที + [ชื่ออำเภอ]" โดยปฏิบัติตามกฎเกณฑ์การทำ Local SEO อย่างเคร่งครัด

---

## 1. Executive Summary (สรุปการดำเนินงาน)

ในส่วนนี้เราได้เปิดใช้งานหน้าบริการใหม่ครอบคลุม 15 อำเภอระดับ P1-P2 ของจังหวัดอุบลราชธานี เพื่อเพิ่มความหนาแน่นของ Keyword ด้านการค้นหาอุปกรณ์ไอทีระดับอำเภอ โดยการ:
1. เปลี่ยนสถานะและตั้งค่า Slug ใน `src/data/districts.json` ให้เป็นภาษาอังกฤษตามหลักการจัดการ URL ที่สะอาด (Clean URLs) และเปลี่ยนสถานะเป็น `"active": true`
2. ป้องกันข้อผิดพลาดของลิงก์ย้อนกลับ (broken paths) ด้วยการแมปชื่ออำเภอภาษาไทยดั้งเดิมเข้าคู่กับ Slug ภาษาอังกฤษใหม่ในระบบกำหนดโครงสร้าง URL (`AREA_SLUGS`)
3. สร้างหน้าเนื้อหาเฉพาะตัว (Unique Content) ปลอดภัยต่อการถูกประเมินเป็น Doorway Pages และไม่มีการใช้คำโปรโมตหรือข้อความที่มีความเสี่ยงเชิงโฆษณา (No Claim Risk)
4. ทำการ Build และรันระบบตรวจสอบความถูกต้องด้าน SEO QA Audit ผ่านเกณฑ์ **PASS 100%** โดยไม่มีข้อผิดพลาด (Errors: 0, Warnings: 0)

## 3. Internal Links Added (การเชื่อมโยงโครงสร้างภายใน)

เพื่อให้ระดับคะแนน Link Equity ไหลเวียนได้อย่างเหมาะสม เราได้วางระบบโครงสร้างลิงก์ภายในอย่างรัดกุม:
1. **ลิงก์จาก Area Hub**: หน้าแรกของพื้นที่ `/พื้นที่/` จะทำการวนลูปนำเข้าข้อมูลและสร้างลิงก์เชื่อมต่อไปยังทั้ง 15 หน้าใหม่โดยอัตโนมัติ เนื่องจากค่าสถานะเปลี่ยนเป็น `"active": true` ใน `districts.json`
2. **ลิงก์กลับไปยัง Hub หลัก**: ทุกหน้าของอำเภอใหม่มีลิงก์ย้อนกลับไปยัง:
   - หน้ารวมพื้นที่ให้บริการ (`/พื้นที่/`)
   - หน้ารวมบริการรับซื้อทั้งหมด (`/บริการ/`)
3. **การเข้าถึง Money Pages สำคัญ**: ด้านในของ YAML Frontmatter (`relatedServices`) และเนื้อหาในส่วนท้ายของทุกหน้า จะลิงก์ออกไปยัง Money Pages หน้าหลักของอุบลราชธานีโดยตรง:
   - [รับซื้อ iPhone อุบล](/บริการ/รับซื้อ-iphone-อุบล/)
   - [รับซื้อ iPad อุบล](/บริการ/รับซื้อ-ipad-อุบล/)
   - [รับซื้อ MacBook อุบล](/บริการ/รับซื้อ-macbook-อุบล/)
   - [รับซื้อโน้ตบุ๊ก อุบล](/บริการ/รับซื้อโน้ตบุ๊ก-อุบล/)
   - [รับซื้อคอมพิวเตอร์ อุบล](/บริการ/รับซื้อคอมพิวเตอร์-อุบล/)
   - [รับซื้อกล้อง อุบล](/บริการ/รับซื้อกล้อง-อุบล/)
4. **ลิงก์พื้นที่ใกล้เคียง (Neighbouring Links)**: มีการแมปเพื่อสร้างลิงก์เชื่อมโยงระนาบเดียวกันในท้องถิ่นจำนวน 2-4 จุดต่ออำเภอ (เช่น `/พื้นที่/samrong/` ลิงก์เชื่อมโยงไปที่ `/พื้นที่/det-udom/` และ `/พื้นที่/warin-chamrap/` เพื่อสร้างเครือข่ายความสัมพันธ์เชิงพื้นที่ทางกายภาพจริง)

## 4. Sitemap & QA Status (การตรวจสอบและผลลัพธ์)

หลังการรันการทดสอบและสแกนโครงสร้างเว็บไซต์จริง:

- **ผลการคอมไพล์ (npm run build)**: สำเร็จสมบูรณ์ โดยเพิ่มจำนวนหน้าทั้งหมดจากเดิมขึ้นมาเป็น 171 หน้าในผลลัพธ์โฟลเดอร์ `dist/`
- **Sitemap Verification**: หน้าใหม่ทั้ง 15 หน้าถูกแทรกลงในแผนผัง sitemap `dist/sitemap-0.xml` อย่างสมบูรณ์ผ่านตัวประมวลผลของ Astro sitemap integration
- **ผลลัพธ์ของ SEO QA Audit (npm run seo:qa)**:
  - **ข้อผิดพลาด (Errors)**: 0
  - **คำเตือน (Warnings)**: 0
  - **ข้อมูลระบุดัชนี (Index status)**: หน้าที่สร้างขึ้นใหม่ทั้งหมดไม่มี tag `noindex` หรือคำสั่งบล็อกบอทใดๆ (พร้อมรับการจัดทำดัชนีในทันที)
  - **ความซ้ำซ้อนของ H1**: มี H1 เพียงรายการเดียวต่อหน้า (ตามมาตรฐาน Google SEO)
  - **ความถูกต้องของ Canonical**: ทุกหน้ามี `link rel="canonical"` ชี้เข้าหาตัวมันเองโดยตรง (Self-canonical) ป้องกันเนื้อหาซ้ำซ้อน

## 5. Remaining Risks (ความเสี่ยงที่คงเหลือและการป้องกัน)

1. **Google Indexing Time**: เนื่องจากเป็นหน้าเว็บที่เพิ่งเกิดใหม่จำนวน 15 หน้า ระบบ Google Bot อาจใช้เวลาในการรวบรวมข้อมูลและทำดัชนี (Index) ประมาณ 1-4 สัปดาห์ ขึ้นอยู่กับรอบการเข้ามาไต่ของบอท
   - *คำแนะนำในการลดความเสี่ยง*: เมื่อทำการ Deploy ขึ้น Live แล้ว ให้ก๊อปปี้ลิงก์ทั้ง 15 หน้าไปส่งคำขอทำดัชนีในทันที (Request Indexing) ผ่าน Google Search Console หรือใช้งาน Google Indexing API เพื่อกระตุ้นระบบโดยด่วน
2. **CDN Cache Discrepancy (Vercel)**: เมื่อนำระบบขึ้น Live ตัว Edge CDN ของ Vercel อาจค้าง Cache หน้า 404 ของ URL ภาษาไทยเดิมก่อนหน้านี้ไว้หากบอทเคยวิ่งเข้ามาก่อน
   - *คำแนะนำในการลดความเสี่ยง*: การ deploy ครั้งถัดไปของ Vercel จะช่วยเคลียร์ Cache ให้หมดสิ้นโดยอัตโนมัติ
